The setting

A data-free universal adversarial perturbation is one image-agnostic perturbation, bounded at 10/255 in the infinity norm, computed from a trained network's weights alone. It never sees a training or test image.

The setting matters twice over. An attacker who obtains a deployed checkpoint, from a model zoo or a shipped application, usually has no access to the proprietary data behind it, so this is the threat that describes the realistic case. And an attack working from weights alone cannot be exploiting a quirk of the data distribution, so whatever it exploits is a property of the learned function.

Four components

The data-free literature developed four separate levers: what to maximise, where in the network to maximise it, what to show the network while doing so, and how to manage the budget during the search. ADAPT-UAP pulls all four at once.

A — Spectral layer weighting

Which layers the objective serves

Each layer's weight tensor is unfolded and decomposed once, from the checkpoint alone. A scalar summary of its spectrum becomes a normalised weight. Three candidate summaries are implemented and reported, not chosen in advance.

B — Truncated ratio maximisation

A per-layer ratio, not a pooled one

A temperature-softened power mean over the strongest retained activations, divided by the magnitude of what the rectifier discards, in logs, weighted per layer by Component A.

C — Multi-scale priors

Structure at three spatial scales

Flat-block fields at 224, 64 and 32, tiled by repetition rather than interpolation, averaged and centred on the dataset mean image. A tile smaller than a deep layer's receptive field repeats across its whole input.

D — Progressive budget

Raised in stages, rescaled not clipped

The budget climbs 2 → 4 → 8 → 10/255 over the run. At each transition the perturbation is rescaled, carrying the direction the previous stage bought into the larger budget instead of flattening it.

The one measured result so far

Every method here reads intermediate activations through forward hooks. A hook receives a reference to a layer's output, not a copy, and PyTorch's vision models build their rectifiers with inplace=True. Wherever a convolution feeds a rectifier directly, the rectifier overwrites the convolution's output buffer before the forward pass returns, and any objective reading that tensor afterwards sees a value with every negative entry already removed.

For an objective built on the positive part this costs nothing, because rectifying twice is rectifying once. For one built on the negative part, which is what a truncated ratio uses as its denominator, it removes the term entirely.

The three collapsed values equal n log(10⁻⁹) exactly, for n = 10, 12, 4. Batch normalisation between the convolution and the rectifier allocates a new tensor, which prevents it.

Three properties make this worth a table rather than a footnote. It is architecture-dependent, so a run that looks correct on one network says nothing about another. It is silent: the run completes, the loss decreases, and the fooling rate is plausible, because a weighting on a constant still produces a number. And it is invisible to the positive part, which is how an implementation passes every check built around the numerator.

The fix is one line, copying the tensor inside the hook, and it must preserve the autograd graph. The detection is equally cheap: compute the negative term once and test whether it equals the degenerate constant. The script that produces this table is released with the paper and needs no GPU, no dataset and no trained weights, because whether a rectifier operates in place is a property of the module rather than of the values flowing through it.

ADAPT-UAP's own denominator is subject to the same hazard. This table is as much a record of a mistake found in its own implementation as it is guidance for anyone else's, and it was found only because an ablation over the ratio's weighting refused to change any result.

Evaluation uses the complete 50,000-image ImageNet validation set; a subsample of a few thousand carries a sampling error comparable to the differences being tested. Every method crafts and is scored through one frozen preprocessing pipeline, fingerprinted twice, so a reported fooling rate traces to the exact pipeline that produced it.

The comparisons, the statistical tests and the multiple-comparison correction are all fixed before the run: a paired bootstrap per architecture, Holm–Bonferroni across the family, and a Wilcoxon signed-rank across architectures. The three design questions the method's description does not settle are left to the ablation rather than decided by the author.
